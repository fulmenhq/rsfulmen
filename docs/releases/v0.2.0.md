# rsfulmen v0.2.0 — stamp-only host identity, producer, goneat v0.6.0

**Release Date**: 2026-09-02

## Overview

Breaking feature release after v0.1.6. Host identity is compile-stamp-only:
missing stamps no longer fill from process `FULMEN_HOST_*`. Application crates
can stamp identity from a `build.rs` producer. goneat is **v0.6.0**. MSRV
remains **1.88**. Embedded Crucible is **v0.4.19**.

Shipped as **0.2.0** because Cargo `^0.1` would take a 0.1.7 and change
`resolve()` for 0.1.6 dependents.

Public history: [PR #15](https://github.com/fulmenhq/rsfulmen/pull/15)
(`5d35eae`), [PR #16](https://github.com/fulmenhq/rsfulmen/pull/16)
(`6cdcfd9`).

## Key Changes

### Stamp-only host identity

`host_identity!()` and `resolve_from_stamps` never read process
`FULMEN_HOST_*`. Missing stamps use documented defaults (`dev` / `unknown` /
omitted dirty). Platform is not derived from the running host at resolve time.

### Producer

Feature `host-identity-producer` (not default). Application `build.rs` calls
`rsfulmen::buildinfo::producer::emit_host_identity()`. Git is probed from
`CARGO_MANIFEST_DIR`. Locator/index/object/config overrides
(`GIT_DIR`, `GIT_WORK_TREE`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_CONFIG*`,
and the rest of the strip set) are not forwarded to Git.

### `resolve()`

**Breaking.** `resolve()` returns documented defaults. It does not read process
environment. Callers that used it as a runtime-env fallback must call
`resolve_from_process_env()`.

### Tooling

- goneat pin **v0.6.0**
- flate2 **1.1.10**, uuid **1.26.0**
- jsonschema 0.17, serde_yaml_ng 0.10, zip 2.x, and direct thiserror 1.x held

## Test Coverage

450 unit tests, 5 host-identity forging tests, 76 doc tests.
`make check-all`; clippy `-D warnings` on 1.98.0; MSRV 1.88 locked tests;
`cargo audit` clean.

## Requirements

- **Rust**: 1.88+ (MSRV, unchanged)
- **Crucible**: v0.4.19 (embedded)

## Migration Guide

If you call `rsfulmen::host_identity!()` you are on the stamp-only path. Stamp
`FULMEN_HOST_*` in the application `build.rs` (producer feature) or accept
documented defaults.

If you call `rsfulmen::buildinfo::resolve()` and expected process
`FULMEN_HOST_*` at runtime, switch to `resolve_from_process_env()`.
