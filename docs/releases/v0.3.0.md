# rsfulmen v0.3.0 — catalogs, telemetry, redaction, std config paths

**Release Date**: 2026-10-20

## Overview

Minor release after v0.2.1. MSRV remains **1.88**. Embedded Crucible remains
**v0.4.19**. Public behavior changes include signal-name resolution,
non-exhaustive catalog types, Prometheus export errors, std-only config
paths, secret redaction, and a registry-wide cap on HTTP metric labels.

## Key Changes

### Config paths

Directory helpers no longer use the `dirs` crate. Absolute
`XDG_CONFIG_HOME`, `XDG_DATA_HOME`, and `XDG_CACHE_HOME` apply on every
platform. Relative or empty values are ignored.

### Telemetry

- Histogram overflow increments `count` and `le="+Inf"` only.
- One metric name accepts one instrument kind.
  `TelemetryError::InstrumentKindConflict` covers acquisition and
  Prometheus text.
- HTTP label sets share a 10_000 cap on the `Metrics` registry. Past the
  cap, route becomes `__other__` and status becomes the outcome class.
- `http_active_requests` uses the service name passed to `HttpRecorder`.

### Logging and signals

- Assignment values for token, secret, password, and API-key fields are
  redacted in log and signal runtime messages. Redaction is best-effort.
- During `listen`, shutdown runs off the listener thread. A second SIGINT
  inside the double-tap window calls `process::exit` and does not use
  `set_force_exit`.

### Release publish

`make release-publish` checks the annotated tag, tagger identity, minisign
attestation, and the tag on the remote before upload. When `origin` is an
SSH host alias, set `RSFULMEN_RELEASE_REPO=fulmenhq/rsfulmen` and push the
tag first.

## Requirements

- **Rust**: 1.88+ (MSRV, unchanged)
- **Crucible**: v0.4.19 (embedded)

## Migration Guide

- Match `TelemetryError` and `#[non_exhaustive]` catalog types with `..`.
- `resolve_signal("-15")` returns `None`. Strip a leading `-` before calling
  it when the input is a kill-style signal.
- `render_prometheus_text` returns `Result`.
- On macOS and Windows, an absolute `XDG_*_HOME` now overrides the platform
  fallback.
