# rsfulmen v0.1.4 — Crucible v0.4.12, five new modules, runtime signal handling

**Release Date**: 2026-02-21

## Overview

Major feature release integrating Crucible v0.4.12 and adding five new modules: typed role catalog, fulencode (encoding/decoding/normalization), runtime signal handling, UUIDv7 correlation IDs, and config env overrides. This is the largest SSOT sync in rsfulmen's history (v0.4.4 → v0.4.12) and brings rsfulmen significantly closer to gofulmen parity.

## Key Changes

### New Modules

| Module                   | Feature               | Description                                               |
| ------------------------ | --------------------- | --------------------------------------------------------- |
| `crucible::roles`        | `crucible`            | Typed agentic role loading from embedded YAML             |
| `fulencode`              | `fulencode`           | Encoding/decoding, detection, normalization, BOM handling |
| `signals::SignalManager` | `foundry-core`        | Runtime signal handler with shutdown/reload chains        |
| `foundry::correlation`   | `foundry-correlation` | UUIDv7 correlation ID generation and validation           |
| `config::env`            | `config`              | Environment variable to config key mapping                |

### Crucible v0.4.12 Sync

Syncs from Crucible v0.4.4 to v0.4.12 — 8 releases of accumulated upstream changes:

- 6 new agentic roles (14 total): cxotech, deliverylead, infraeng, qa, releng, uxdev
- Updated role-prompt schema: domains, pre_push_checklist, required_reading, cross_role_note
- Fulencode schemas (11 files), fixtures (6 files), and text-safe normalization standard
- Design token schemas (TUI themes, typography, spacing, colors)
- Expanded upstream standards and architecture docs

### Typed Role Catalog (`crucible::roles`)

Full-fidelity `RolePrompt` deserialization with all 22 fields from `role-prompt.schema.json`. Follows the foundry catalog pattern (Lazy + serde_yaml). Forward-compatible enums with `#[serde(other)]`. Invariant-based tests per cross-team agreement.

### Fulencode (`fulencode`)

5 canonical operations: `encode()`, `decode()`, `detect()`, `normalize()`, BOM handling. Supports Base64, Base64URL, Hex, UTF-8, UTF-16LE/BE encoding formats and NFC/NFD/NFKC/NFKD + text-safe normalization profiles. Cross-language parity via fixture-driven tests from Crucible SSOT.

### Runtime Signal Handling (`signals`)

`SignalManager` with thread-safe handler dispatch, LIFO shutdown chains, FIFO reload chains, SIGINT double-tap with catalog-driven defaults, and `SignalInjector` for tests. Cross-platform: `signal-hook` on Unix, `ctrlc` on Windows.

### Correlation IDs (`foundry::correlation`)

UUIDv7 generation, parsing, and validation. `CorrelationId` newtype strictly enforces v7 (rejects v4). Serde roundtrip validates on deserialize. Uppercase input normalized to lowercase canonical form.

### Config Env Overrides (`config::env`)

Maps environment variables to nested config keys with type parsing (String/Int/Float/Bool), alias support, conflict detection, and sensitive value masking. Diagnostic report tracks which vars were applied and any conflicts. Output feeds directly into `load_three_layer()` as `runtime_overrides`.

### Bug Fixes

- **Pathfinder temp-dir race**: parallel tests could collide on same-nanosecond timestamps. Fixed with `AtomicU64` sequence counter.
- **CI yamllint**: fixed missing space before inline comment in `ci.yml`.

## Migration Guide

No breaking changes. All new functionality is additive. Existing code compiles and runs without modification.

To use new modules:

```rust
// Typed role catalog
use rsfulmen::crucible::roles::{load_role, RoleStatus};
let role = load_role("devlead").unwrap();

// Fulencode
use rsfulmen::fulencode::{self, EncodingFormat};
let result = fulencode::encode(b"hello", EncodingFormat::Base64, None).unwrap();

// Correlation IDs
use rsfulmen::foundry::correlation;
let id = correlation::generate();

// Signal handling
use rsfulmen::signals::SignalManager;
let manager = SignalManager::new();

// Env overrides
use rsfulmen::config::env::{self, EnvVarSpec, EnvVarType};
let overrides = env::load_env_overrides(&specs).unwrap();
```
